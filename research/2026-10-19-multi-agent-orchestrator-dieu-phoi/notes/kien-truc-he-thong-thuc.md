## Câu hỏi phụ 1: Các kiến trúc điều phối phổ biến và cách hệ thống thật cài đặt

### Kết luận ngắn
Có 4 họ kiến trúc cài đặt rõ trong code: (a) **agent-as-tool / supervisor**: orchestrator gọi subagent như một tool rồi giữ quyền điều khiển (Anthropic Research, Claude Code/Agent SDK, OpenAI `as_tool`, LangChain "subagents", ADK `AgentTool`/single_turn); (b) **handoff**: chuyển quyền điều khiển, agent mới "tiếp quản" hội thoại (OpenAI handoffs, LangGraph swarm, ADK `transfer_to_agent`); (c) **group chat có manager LLM chọn người nói** (AutoGen Selector, Magentic-One với ledger); (d) **workflow cứng bằng code** (ADK Sequential/Parallel/Loop agent, OpenAI "orchestrating via code"). Hierarchical chỉ là (a) lồng nhiều tầng. Mức chắc chắn: **cao**, vì đều đọc từ docs chính thức và source code.

### Phát hiện có nguồn

**Định nghĩa gốc**
- Anthropic định nghĩa orchestrator-workers: "a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results". Khác với parallelization ở chỗ "subtasks aren't pre-defined, but determined by the orchestrator based on the specific input". Bài cũng phân biệt workflow ("LLMs and tools are orchestrated through predefined code paths") với agent ("LLMs dynamically direct their own processes and tool usage"). — [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (bậc 1, 2024-12-19)

**Anthropic multi-agent Research**
- Kiến trúc orchestrator-worker: LeadResearcher lập kế hoạch rồi "uses tools to create parallel agents that search for information simultaneously". Lead chạy 3–5 subagent song song; mỗi subagent dùng "3+ tools in parallel". — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Quy tắc scale ghi trong prompt: tìm fact đơn giản dùng 1 agent với 3–10 tool call; so sánh trực tiếp dùng 2–4 subagent, mỗi cái 10–15 call; nghiên cứu phức tạp dùng hơn 10 subagent. Bản đầu từng lỗi "spawning 50 subagents for simple queries". — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Sau vòng research, một CitationAgent riêng xử lý tài liệu và báo cáo để gắn trích dẫn. — cùng nguồn (bậc 1, 2025-06-13)
- Prompt lead agent đã công bố (cookbook) nêu tên tool giao việc `run_blocking_subagent` (tham số `prompt`), mặc định 3 subagent, "Never create more than 20 subagents unless strictly necessary", và yêu cầu "You MUST use parallel tool calls for creating multiple subagents". Lead nộp báo cáo cuối bằng tool `complete_task` và không tự viết citation ("a separate agent will be responsible for citations"). — [research_lead_agent.md](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/prompts/research_lead_agent.md) (bậc 1, không rõ ngày; công bố kèm bài 2025-06)
- Số liệu (Anthropic tự báo cáo): hệ multi-agent (lead Opus 4, subagent Sonnet 4) hơn single-agent Opus 4 **90,2%** trên eval research nội bộ. Trên BrowseComp, lượng token giải thích 80% phương sai (cộng số tool call và lựa chọn model thì 95%). Multi-agent tốn khoảng **15×** token so với chat (agent đơn khoảng 4×). Song song hoá cắt tới 90% thời gian với truy vấn phức tạp. — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)

**Claude Code subagents / Claude Agent SDK**
- "Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions." Main agent tự quyết delegate dựa vào field `description` của subagent. — [Create custom subagents (Claude Code docs)](https://code.claude.com/docs/en/sub-agents) (bậc 1, truy cập 2026-10-19)
- Tool giao việc tên là `Agent`: "In version 2.1.63, the Task tool was renamed to Agent", và `Task(...)` vẫn là alias. — cùng nguồn (bậc 1)
- Lồng nhiều tầng (hierarchical): mặc định một subagent được spawn subagent con "up to three layers below the main conversation" (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). Tối đa 20 subagent chạy đồng thời (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), quá ngưỡng thì trả lỗi `Concurrent subagent limit reached`. — cùng nguồn (bậc 1)
- **Fork** là biến thể khác hẳn subagent thường: "A fork is a subagent that inherits the entire conversation so far instead of starting fresh". Fork dùng cùng system prompt và tool với main nên tái dùng prompt cache. Fork mode bật mặc định trong phiên interactive và tắt mặc định ở `-p`/Agent SDK. — cùng nguồn (bậc 1)
- Agent SDK định nghĩa subagent qua `AgentDefinition` (`description`, `prompt`, `tools`, `model`, `maxTurns`, `background`, `skills`, `memory`…). Cho job lớn "dozens to hundreds of agents", SDK khuyên dùng tool `Workflow`, tức chuyển orchestration ra một script chạy ngoài context hội thoại. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1, truy cập 2026-10-19)
- Riêng Opus 5: "Claude Opus 5 delegates to subagents more readily than earlier models". Preset `claude_code` vì thế thêm một dòng system prompt dặn không gọi Agent tool trừ khi được yêu cầu. — cùng nguồn (bậc 1)

**OpenAI Agents SDK**
- Hai pattern lõi trong SDK: "Agents as tools: A manager agent keeps control of the conversation and calls specialist agents through `Agent.as_tool()`" và "Handoffs: A triage agent routes the conversation to a specialist, and that specialist becomes the active agent for the rest of the turn". Hai pattern có thể kết hợp. Ngoài ra còn "Orchestrating via code": structured output để phân loại, chaining, vòng `while` có evaluator, `asyncio.gather`. — [docs/multi_agent.md](https://github.com/openai/openai-agents-python/blob/main/docs/multi_agent.md) (bậc 1, repo 2026-10-17)
- Docstring `as_tool` nêu đúng hai khác biệt: "In handoffs, the new agent receives the conversation history. In this tool, the new agent receives generated input." và "In handoffs, the new agent takes over the conversation. In this tool, the new agent is called as a tool, and the conversation is continued by the original agent." — [src/agents/agent.py](https://github.com/openai/openai-agents-python/blob/main/src/agents/agent.py) (bậc 1, repo 2026-10-17)
- "Handoffs are represented as tools to the LLM": handoff tới `Refund Agent` hiện ra dưới dạng tool `transfer_to_refund_agent`. — [docs/handoffs.md](https://github.com/openai/openai-agents-python/blob/main/docs/handoffs.md) (bậc 1, repo 2026-10-17)
- Guide PDF "A practical guide to building agents" (manager pattern vs decentralized pattern) **không mở được** (cdn.openai.com bị chặn). Các bản tóm tắt thứ cấp mô tả manager = agents-as-tools và decentralized = handoff "one way transfer". — [agentic-ai.readthedocs.io](https://agentic-ai.readthedocs.io/en/latest/DesignPatterns/openai-patterns/) (bậc 3, chỉ dùng làm manh mối)

**LangGraph / LangChain**
- LangChain liệt kê 5 pattern: Subagents ("A main agent coordinates subagents as tools. All routing passes through the main agent"), Handoffs ("Tool calls update a state variable that triggers routing"), Skills, Router, Custom workflow. Tài liệu cũng nhấn mạnh "At the center of multi-agent design is context engineering". — [multi-agent/index.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/index.mdx) (bậc 1, repo 2026-10-18)
- Phân biệt supervisor với router: supervisor là "a full agent that maintains conversation context and dynamically decides which subagents to call across multiple turns", còn router "is typically a single classification step". — [multi-agent/subagents.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/subagents.mdx) (bậc 1, repo 2026-10-18)
- Thư viện `langgraph-supervisor` hiện tự khuyên không dùng: "We now recommend using the supervisor pattern directly via tools rather than this library for most use cases. The tool-calling approach gives you more control over context engineering". — [langgraph-supervisor-py README](https://github.com/langchain-ai/langgraph-supervisor-py) (bậc 1, repo 2026-07-14)
- Trong `langgraph-supervisor`, supervisor là một ReAct agent có các handoff tool `transfer_to_<agent>`. Mỗi worker là một node trong graph, và có cạnh cố định quay về supervisor (`builder.add_edge(agent.name, supervisor_agent.name)`). — [supervisor.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/supervisor.py) (bậc 1, repo 2026-07-14)
- `langgraph-swarm` (handoff ngang hàng, không có trung tâm): handoff tool trả `Command` cập nhật `active_agent` trong state, và lượt sau router chuyển thẳng tới agent đang active. — [langgraph_swarm/handoff.py, swarm.py](https://github.com/langchain-ai/langgraph-swarm-py) (bậc 1, repo 2026-09-19)
- So sánh định lượng do LangChain tự dựng (ví dụ minh hoạ, không phải benchmark độc lập): một yêu cầu đơn tốn 4 model call với Subagents và 3 với Handoffs/Skills/Router. Với tác vụ đa miền (so sánh 3 ngôn ngữ), Subagents tốn 5 call ~9K token, Handoffs 7+ call ~14K+ token (vì "must execute sequentially"), Skills 3 call ~15K token. Tài liệu viết: "Subagents processes 67% fewer tokens overall due to context isolation". — [multi-agent/index.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/index.mdx) (bậc 1, repo 2026-10-18)

**Microsoft Magentic-One / AutoGen**

Nó có hai vòng lặp: "an outer loop where it updates the Task Ledger and an inner loop to update the Progress Ledger". - AutoGen còn các team kiểu group chat: RoundRobin, Selector (một LLM đọc `roles` và lịch sử rồi chọn người nói tiếp), Swarm (handoff), GraphFlow. — [teams/_group_chat/](https://github.com/microsoft/autogen/tree/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat) (bậc 1, repo 2026-10-16)

**Google ADK**
- Pattern "Coordinator and dispatcher": một `LlmAgent` trung tâm có `sub_agents`. Có hai cách giao việc: **LLM-Driven Delegation** (LLM gọi `transfer_to_agent(agent_name=...)`) hoặc **Explicit Invocation (`AgentTool`)**. Ngoài ra có workflow cứng: `SequentialAgent`, `ParallelAgent` (fan-out/gather qua shared session state), `LoopAgent`. — [docs/workflows/patterns.md](https://github.com/google/adk-docs/blob/main/docs/workflows/patterns.md) (bậc 1, repo 2026-10-16)

### Nhận định
- **Nhận định:** Ở mức API, mọi framework đều quy về một primitive: **tool call**. Agent-as-tool và handoff đều được trình bày với LLM như một function tool (`run_blocking_subagent`, `Agent`, `transfer_to_<x>`, `transfer_to_agent`, `task`). Chúng chỉ khác nhau ở việc runtime làm gì sau tool call: chạy một vòng agent lồng rồi trả tool_result, hay đổi agent active và chuyển lịch sử sang.
- **Nhận định:** Xu hướng 2025–2026 là bỏ thư viện supervisor chuyên dụng để tự viết "supervisor via tools" (LangChain), cũng như bỏ `AgentTool` trực tiếp để dùng `mode='single_turn'` (ADK). Lý do chung là muốn kiểm soát context engineering. Magentic-One là ngoại lệ đáng chú ý: không dùng tool call mà dùng group chat với ledger JSON. Đây là kiến trúc có cơ chế bám mục tiêu tường minh nhất (xem câu hỏi phụ 2).
- **Nhận định:** Con số 90,2% và 15× là do Anthropic tự báo cáo trên eval nội bộ, chưa có kiểm chứng độc lập. Bảng so sánh của LangChain là ví dụ minh hoạ, không phải đo thực nghiệm.

## Câu hỏi phụ 2: Cơ chế giao việc và nhận kết quả

### Kết luận ngắn
Trong các hệ agent-as-tool, subagent được gọi bằng **một tool call**. Subagent chạy một vòng agent riêng với context mới, và chỉ **tin nhắn cuối** (final output) quay về orchestrator dưới dạng **tool_result**; transcript bên trong bị giữ lại. Orchestrator biết subagent xong khi tool call trả về (sync), hoặc khi nhận một **completion notification** ở lượt sau (background). Song song đạt được bằng cách model phát nhiều tool call trong một response và runtime chạy chúng đồng thời. Handoff thì ngược lại: chuyển cả lịch sử sang và không có "kết quả trả về". Magentic-One không dùng tool_result mà dùng thread tin nhắn chung, mỗi lượt chỉ định đích danh một agent. Mức chắc chắn: **cao** (source code và docs chính thức).

### Phát hiện có nguồn

**Đầu vào gửi cho subagent**
- Claude Agent SDK: "The only content you pass from parent to subagent is the Agent tool's prompt string, so include any file paths, error messages, or decisions the subagent needs directly in that prompt." Subagent thường (không phải fork) nhận system prompt riêng (`AgentDefinition.prompt`), prompt của Agent tool, CLAUDE.md và tool definitions. Nó **không** nhận lịch sử hội thoại, tool result hay system prompt của parent. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1, truy cập 2026-10-19)
- Claude Code: "Claude composes a delegation message that summarizes the task, and the subagent works from there." — [Create custom subagents](https://code.claude.com/docs/en/sub-agents) (bậc 1, truy cập 2026-10-19)
- OpenAI `as_tool`: mặc định input là `{"input": "..."}`, có thể khai schema có cấu trúc qua `parameters`. "the parent run's conversation state is not inherited automatically"; muốn chia sẻ thì phải truyền cùng `session`. — [docs/tools.md](https://github.com/openai/openai-agents-python/blob/main/docs/tools.md) (bậc 1, repo 2026-10-17)
- LangChain "single dispatch tool": một tool `task(agent_name, description)`, trong đó "the task description is passed as a human message to the sub-agent, and the sub-agent's final message is returned as the tool result". — [subagents.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/subagents.mdx) (bậc 1, repo 2026-10-18)
- ADK `AgentTool.run_async`: tạo một `Runner` mới với `InMemorySessionService()` và một session con, copy state của parent (bỏ key `_adk*`), chạy agent, rồi chuyển `state_delta` ngược về session cha. — [agent_tool.py](https://github.com/google/adk-python/blob/main/src/google/adk/tools/agent_tool.py) (bậc 1, repo 2026-10-18)

**Kết quả quay về dạng gì**
- Claude Agent SDK: "intermediate tool calls and results stay inside the subagent; only its final message returns to the parent". Khi subagent xong, tool result của Agent tool có thêm một text block `agentId: <id>` để resume sau. Nếu chạm `maxTurns`, output bị đánh dấu partial. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1, truy cập 2026-10-19)
- Claude Code quét báo cáo cuối của subagent trước khi model chính đọc. Từ v2.1.210, tag kiểu `<system-reminder>` bị vô hiệu hoá và dòng bắt đầu bằng `Human:`/`Assistant:` được escape, để báo cáo không giả được ranh giới lượt; nội dung khác giữ nguyên. — cùng nguồn (bậc 1)
- OpenAI `as_tool` (source): trả `run_result.final_output`. Nếu final output rỗng thì quét ngược `new_items` lấy message text hoặc tool output gần nhất không rỗng. `custom_output_extractor` cho phép trích/định dạng lại (ví dụ chỉ lấy JSON payload). — [agent.py](https://github.com/openai/openai-agents-python/blob/main/src/agents/agent.py), [docs/tools.md](https://github.com/openai/openai-agents-python/blob/main/docs/tools.md) (bậc 1, repo 2026-10-17)
- ADK `AgentTool`: lấy `last_content` (event có content cuối), nối text các part và bỏ part `thought`, rồi trả làm tool result (validate theo `output_schema` nếu có). Cờ `skip_summarization` cho phép bỏ bước LLM cha tóm tắt lại kết quả. — [agent_tool.py](https://github.com/google/adk-python/blob/main/src/google/adk/tools/agent_tool.py) (bậc 1, repo 2026-10-18)
- LangGraph supervisor có `output_mode`: `"last_message"` (mặc định, chỉ thêm tin cuối của worker vào lịch sử supervisor) hoặc `"full_history"`. Mặc định nó còn chèn cặp giả `AIMessage` "Transferring back to supervisor" + `ToolMessage` "Successfully transferred back to supervisor" (`add_handoff_back_messages`) để supervisor thấy quyền đã trả về. — [supervisor.py, handoff.py](https://github.com/langchain-ai/langgraph-supervisor-py/tree/main/langgraph_supervisor) (bậc 1, repo 2026-07-14)
- LangChain cảnh báo lỗi thường gặp: "the sub-agent performs tool calls or reasoning but doesn't include results in its final message—remind it that the supervisor only sees the final output". — [subagents.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/subagents.mdx) (bậc 1, repo 2026-10-18)
- Anthropic Research: ngoài kết quả trực tiếp, bài viết mô tả pattern artifact: "Subagents call tools to store their work in external systems, then pass lightweight references back to the coordinator" (mục "Subagent output to a filesystem to minimize the 'game of telephone'"). Subagent đóng vai "intelligent filters" vì "The essence of search is compression". — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- ADK workflow agents trả kết quả qua **shared session state** thay vì tool_result: subagent ghi `output_key` (ví dụ `api1_data`), agent "Gather" đọc các key đó. — [patterns.md](https://github.com/google/adk-docs/blob/main/docs/workflows/patterns.md) (bậc 1, repo 2026-10-16)

**Handoff: chuyển lịch sử, không có kết quả trả về**
- OpenAI: "When a handoff occurs, it's as though the new agent takes over the conversation, and gets to see the entire previous conversation history." Có thể lọc bằng `input_filter` (ví dụ `handoff_filters.remove_all_tools`). Ngoài ra có `nest_handoff_history` (beta, tắt mặc định) để nén lịch sử thành đoạn tóm tắt bọc trong `<CONVERSATION HISTORY>`. — [docs/handoffs.md](https://github.com/openai/openai-agents-python/blob/main/docs/handoffs.md) (bậc 1, repo 2026-10-17)
- OpenAI runner: nếu model gọi nhiều handoff trong một lượt, chỉ cái đầu được thực hiện; các cái sau nhận tool output "Multiple handoffs detected, ignoring this one." — [run_internal/turn_resolution.py](https://github.com/openai/openai-agents-python/blob/main/src/agents/run_internal/turn_resolution.py) (bậc 1, repo 2026-10-17)
- LangGraph handoff tool trả `Command(goto=agent_name, graph=Command.PARENT, update={... "messages": ...})` kèm `ToolMessage` "Successfully transferred to <agent>". Nếu có nhiều handoff song song, mỗi cái thành một `Send(agent_name, ...)`. — [handoff.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/handoff.py) (bậc 1, repo 2026-07-14)
- ADK: `transfer_to_agent(agent_name, transfer_reason)` chỉ set `tool_context.actions.transfer_to_agent = agent_name`; runtime đọc cờ đó để chuyển agent. — [transfer_to_agent_tool.py](https://github.com/google/adk-python/blob/main/src/google/adk/tools/transfer_to_agent_tool.py) (bậc 1, repo 2026-10-18)

**Song song hay tuần tự**
- Anthropic Research: song song trong một đợt (3–5 subagent qua parallel tool call), nhưng **đồng bộ giữa các đợt**: "Currently, our lead agents execute subagents synchronously, waiting for each set of subagents to complete before proceeding". Bài coi đây là nút cổ chai, async là hướng tương lai. — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Claude Code/Agent SDK (10/2026): "Subagents run in the background by default"; Claude đặt `run_in_background: false` khi cần kết quả trước khi đi tiếp. Khi fork mode bật (mặc định trong interactive), mọi subagent chạy background và tham số `run_in_background` bị gỡ. — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), [sub-agents](https://code.claude.com/docs/en/sub-agents) (bậc 1, truy cập 2026-10-19)
- OpenAI SDK: `ModelSettings.parallel_tool_calls` quyết định model có được phát nhiều tool call trong một response hay không. Khi model đã phát, mặc định SDK "starts all emitted local function tool calls" đồng thời; `tool_execution.max_function_tool_concurrency` đặt trần. — [docs/running_agents.md](https://github.com/openai/openai-agents-python/blob/main/docs/running_agents.md) (bậc 1, repo 2026-10-17)
- LangGraph supervisor mặc định `parallel_tool_calls=False` (chỉ OpenAI và Anthropic hỗ trợ tắt), tức supervisor giao từng worker một. — [supervisor.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/supervisor.py) (bậc 1, repo 2026-07-14)
- LangChain: sync (mặc định, "the main agent waits for each subagent to complete") khác async (job nền: start job trả job ID, check status, get result). Khi job xong, ứng dụng phải tự báo, ví dụ gửi `HumanMessage` "Check job_123 and summarize the results." — [subagents.mdx](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/multi-agent/subagents.mdx) (bậc 1, repo 2026-10-18)
- ADK: chỉ `single_turn` chạy song song được. Mỗi agent task/single_turn "operates in its own isolated session branch… cannot see what its peer agents are doing. Once all parallel branches complete, the parent agent receives the collected results". — [collaboration.md](https://github.com/google/adk-docs/blob/main/docs/workflows/collaboration.md) (bậc 1, repo 2026-10-16)
- Magentic-One: tuần tự hoàn toàn, mỗi bước Orchestrator chọn đúng **một** `next_speaker`. — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py) (bậc 1, repo 2026-10-16)

**Orchestrator biết subagent đã xong bằng cách nào**
- Sync/tool: subagent xong khi vòng lặp agent con kết thúc, tức là khi model con trả text không kèm tool call. Runner OpenAI ghi: "If the runner classifies the LLM's output as final output, the loop ends"; final output là "text output with the desired type, and there are no tool calls". Nếu vượt `max_turns`, runner raise `MaxTurnsExceeded`. — [docs/running_agents.md](https://github.com/openai/openai-agents-python/blob/main/docs/running_agents.md) (bậc 1, repo 2026-10-17)
- Tool tường minh "tôi xong rồi": prompt subagent của Anthropic Research yêu cầu "As soon as the task is done, immediately use the `complete_task` tool to finish and provide your detailed, condensed, complete, accurate report to the lead researcher". Prompt cũng đặt trần cứng: "stay under a limit of 20 tool calls and under about 100 sources… If you exceed this limit, the subagent will be terminated". — [research_subagent.md](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/prompts/research_subagent.md) (bậc 1, không rõ ngày)
- ADK `task` mode: subagent chạy "until it calls `finish_task`. At that point, control automatically returns to the originating agent"; chế độ `chat` thì phải gọi `transfer_to_agent` để trả quyền. — [collaboration.md](https://github.com/google/adk-docs/blob/main/docs/workflows/collaboration.md) (bậc 1, repo 2026-10-16)
- Background trong Claude Code: "A background subagent's results reach Claude as a completion notification in a later turn. Claude waits for that notification before reporting the subagent's results". Notification "is marked as an automated event rather than a message from you". Trước v2.1.211, Claude đôi khi báo kết quả cho subagent chưa xong. Có thêm hook `SubagentStart`/`SubagentStop` cho code bên ngoài. — [sub-agents](https://code.claude.com/docs/en/sub-agents) (bậc 1, truy cập 2026-10-19)
- Lỗi: ở foreground, nếu API error cắt ngang thì Agent tool trả output dở dang "with a note that the subagent was cut off"; nếu chưa có text thì báo `Agent terminated early due to an API error`. Ở background, subagent bị đánh dấu failed, và thông báo gửi về có tên lỗi cùng output cuối. — cùng nguồn (bậc 1)
- Magentic-One: worker trả lời bằng `GroupChatAgentResponse`; handler `handle_agent_response` thêm `chat_message` vào `_message_thread` rồi gọi `_orchestrate_step` cho bước kế. Nhiệm vụ kết thúc khi Progress Ledger trả `is_request_satisfied=true` (khi đó gọi `_prepare_final_answer`) hoặc khi vượt `max_turns`. — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py) (bậc 1, repo 2026-10-16)
- Anthropic Research: ở cấp lead, "The LeadResearcher synthesizes these results and decides whether more research is needed". Prompt lead yêu cầu dừng khi gặp "diminishing returns" rồi gọi `complete_task`. — [bài blog](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13); [research_lead_agent.md](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/prompts/research_lead_agent.md) (bậc 1)

**Orchestrator thấy gì về công việc bên trong subagent**

Subagent tự auto-compact trong context của nó. Muốn hỏi tiếp thì **resume**: "Resumed subagents retain their full conversation history" (qua `SendMessage` hoặc `resume: sessionId` cùng agentId). — [sub-agents](https://code.claude.com/docs/en/sub-agents), [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1, truy cập 2026-10-19)

**Cơ chế bám mục tiêu cài sẵn trong vòng lặp Magentic-One (liên quan câu hỏi phụ 3–4; để writer tham chiếu)**
- Bước đầu (outer loop), hai lượt gọi model riêng: (1) prompt "pre-survey" lập fact sheet gồm 4 mục: GIVEN OR VERIFIED FACTS / FACTS TO LOOK UP / FACTS TO DERIVE / EDUCATED GUESSES; (2) lập "short bullet-point plan" dựa trên thành phần team. — [_prompts.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_prompts.py) (bậc 1, repo 2026-10-16)
- `_reenter_outer_loop`: reset mọi agent (`GroupChatReset`), **xoá** `_message_thread`, rồi đặt một tin Task Ledger duy nhất ("We are working to address the following user request: {task} … team … facts … plan") làm tin đầu thread và broadcast cho mọi agent. — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py) (bậc 1)
- Mỗi bước inner loop, Orchestrator gửi model: toàn bộ thread hiện tại, và ở cuối một `UserMessage` Progress Ledger mở đầu "Recall we are working on the following request: {task}". Model phải trả JSON 5 trường: `is_request_satisfied`, `is_in_loop`, `is_progress_being_made`, `next_speaker`, `instruction_or_question` (mỗi trường có `reason` + `answer`). Câu trả lời `instruction_or_question` được broadcast thành tin của Orchestrator, rồi agent `next_speaker` nhận `GroupChatRequestPublish`. — cùng nguồn (bậc 1)
- Đếm stall: `n_stalls += 1` nếu không tiến triển hoặc đang lặp, ngược lại giảm 1 (không dưới 0). Khi `n_stalls >= max_stalls` (mặc định **3**), log "Stall count exceeded, re-planning with the outer loop...", cập nhật facts (prompt "As a reminder, we are working to solve the following task: {task}…") và plan ("explain what went wrong… new plan… avoids repeating the same mistakes"), rồi vào lại outer loop. — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py), [_magentic_one_group_chat.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_group_chat.py) (bậc 1, repo 2026-10-16)
- Câu trả lời cuối dùng prompt riêng: "We are working on the following task: {task} … Based on the information gathered, provide the final answer to the original request." — [_prompts.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_prompts.py) (bậc 1)
- Anthropic Research: lead lưu plan vào Memory "since if the context window exceeds 200,000 tokens it will be truncated and it is important to retain the plan". Agent có thể "spawn fresh subagents with clean contexts while maintaining continuity through careful handoffs". — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)

### Nhận định
- **Nhận định:** Giao thức chung ở mức API cho agent-as-tool: lượt N của orchestrator phát `tool_use{name: Agent|task|<agent_tool>, input: {prompt/description}}`. Runtime chạy một vòng agent con độc lập, với system prompt riêng cộng đúng chuỗi prompt đó làm user message. Vòng con dừng khi model con trả text không có tool call (hoặc gọi tool kết thúc như `complete_task`/`finish_task`, hoặc chạm trần lượt). Lượt N+1 của orchestrator nhận `tool_result` chứa văn bản cuối đó, kèm metadata nếu có (agentId, cờ partial). Mọi thứ subagent "biết" nhưng không viết vào tin cuối đều mất với orchestrator. Vì vậy cả Anthropic lẫn LangChain đều nhấn mạnh việc quy định định dạng đầu ra cho subagent.
- **Nhận định:** Có hai trục thiết kế độc lập: (1) **context vào**: chỉ prompt (Claude subagent thường, OpenAI as_tool, LangChain task), toàn bộ lịch sử (fork, handoff), hay state chung (ADK output_key); (2) **kết quả ra**: tin cuối (mặc định hầu hết), toàn bộ lịch sử (`full_history`), tham chiếu tới artifact/file (Anthropic), hay key trong state (ADK).
- **Nhận định:** Magentic-One là hệ duy nhất trong nhóm này **lặp lại task gốc nguyên văn ở mỗi lượt gọi model của orchestrator** (Progress Ledger mở đầu bằng "Recall we are working on the following request: {task}"), và **xoá lịch sử để đặt lại ledger** khi replan. Đây là bằng chứng code-level rõ nhất cho câu hỏi "bám mục tiêu bằng cách nào". Các hệ tool-based dựa vào việc task gốc vẫn nằm trong lịch sử hội thoại của orchestrator (user message đầu tiên), cộng plan lưu ngoài (Anthropic Memory).
- **Nhận định:** Background/async làm phát sinh bài toán "biết khi nào xong". Claude Code giải bằng completion notification chèn vào một lượt sau (và từng có bug báo sớm trước v2.1.211); LangChain để ứng dụng tự lo. Anthropic Research cố ý giữ sync giữa các đợt vì đơn giản hơn để điều phối.

### Khoảng trống
- Không có tài liệu chính thức mô tả nguyên văn định dạng `tool_result` mà Claude Code chèn cho Agent tool, ngoài các chi tiết "final message", "`agentId: <id>` text block" và "partial". Muốn có ví dụ JSON đầy đủ thì phải bắt traffic thật.
- Hệ Research của Anthropic không công bố code production. Cơ chế "Memory", "external systems" và "lightweight references" chỉ được mô tả bằng lời.
- Cơ chế ADK `single_turn` trả kết quả về parent (tool response tự sinh hay event gom nhánh) mới đọc ở mức docs, chưa đọc source `flows/llm_flows`.
