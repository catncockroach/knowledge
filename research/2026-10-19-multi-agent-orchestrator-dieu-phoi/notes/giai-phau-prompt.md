Ghi chú chung về nguồn: các file prompt (Anthropic cookbook, OpenAI Agents SDK, AutoGen Magentic-One, langgraph-supervisor) được tải thẳng từ `raw.githubusercontent.com` nhánh `main` ngày 2026-10-19 và đọc nguyên văn. Trang blog Manus và docs OpenAI (developers.openai.com, openai.github.io) **không mở được** do proxy/DNS chặn; phần Manus và OpenAI conversation-state dựa trên snippet search trích từ chính trang gốc, đã ghi rõ ở từng dòng.

## Câu hỏi phụ 3a: Request gửi cho orchestrator ở lượt N gồm những gì? Vòng lặp agent stateless chạy ra sao?

### Kết luận ngắn
Model không giữ trạng thái giữa các lần gọi: mỗi lượt, harness gửi lại **toàn bộ** request gồm `tools` (trong đó có tool "spawn subagent"), `system`, và mảng `messages` chứa task gốc của user + mọi cặp `assistant tool_use` / `user tool_result` trước đó + các đoạn chèn thêm (reminder, ledger, todo). "Bám mục tiêu" ở mức API nghĩa là task gốc vẫn nằm trong prefix được gửi lại, hoặc được harness chủ động nhắc lại ở cuối context. Mức chắc chắn: **cao** (docs chính thức Anthropic + source code AutoGen/LangGraph).

### Phát hiện có nguồn
- Messages API stateless: "The Messages API is stateless, which means that you always send the full conversational history to the API." Các lượt assistant trước đó còn có thể là message tổng hợp (synthetic) — [Using the Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) (bậc 1, truy cập 2026-10-19)
- Khi request có `tools`, API tự dựng một system prompt đặc biệt theo thứ tự: câu mở "In this environment you have access to a set of tools you can use to answer the user's question.", `{{ FORMATTING INSTRUCTIONS }}`, "Here are the functions available in JSONSchema format:", `{{ TOOL DEFINITIONS IN JSON SCHEMA }}`, `{{ USER SYSTEM PROMPT }}`, `{{ TOOL CONFIGURATION }}`. Tức là định nghĩa tool (kể cả tool gọi subagent) nằm **trước** system prompt của người dùng trong cái model thấy — [Define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) (bậc 1, truy cập 2026-10-19)
- Một tool definition gồm `name` (regex `^[a-zA-Z0-9_-]{1,128}$`), `description`, `input_schema` (JSON Schema), tùy chọn `input_examples`; docs khuyên mô tả "at least 3–4 sentences", gộp thao tác liên quan vào ít tool hơn, và trả về "only high-signal information" — [Define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) (bậc 1)
- Vòng lặp: response có `stop_reason: "tool_use"` và block `tool_use` {`id`, `name`, `input`}; client chạy tool rồi gửi message `role: user` chứa block `tool_result` {`tool_use_id`, `content`, `is_error`}. Ràng buộc: "Tool result blocks must immediately follow their corresponding tool use blocks… You cannot include any messages between…"; "the tool_result blocks must come FIRST in the content array. Any text must come AFTER all tool results." (text đứng trước tool_result → lỗi 400) — [Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls) (bậc 1)
- Claude API không có role `tool` riêng: "the Claude API integrates tools directly into the `user` and `assistant` message structure" (khác OpenAI dùng role `tool`/`function`) — [Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls) (bậc 1)
- Cảnh báo bảo mật liên quan trực tiếp tới kết quả subagent: nội dung tool result là "untrusted"; "Keep untrusted content inside `tool_result` blocks rather than `system` prompts or plain user `text` blocks" — [Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls) (bậc 1)
- Claude Agent SDK: subagent được gọi qua tool tên `Agent` (trước v2.1.63 là `Task`); input có `subagent_type`, `prompt`, `run_in_background`; khi xong, Agent tool result chứa text "agentId: <id>"; message từ bên trong subagent mang `parent_tool_use_id`. "only its final message returns to the parent" — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1, truy cập 2026-10-19)
- Subagent chạy nền mặc định: Agent tool call không có `run_in_background` sẽ chạy background; kết quả "reach Claude as a completion notification in a later turn" — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents); [Create custom subagents](https://code.claude.com/docs/en/sub-agents) (bậc 1)
- Harness Claude Code có chèn thẻ riêng vào context: docs nói Claude Code "neutralizes a tag that only the harness emits, such as a `<system-reminder>` block" khi thẻ đó xuất hiện trong output subagent — xác nhận rằng `<system-reminder>` là kênh chèn của harness vào messages — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1)
- Kênh chèn chỉ dẫn giữa chừng chính thức: trên các model Claude mới, có thể đặt message `"role": "system"` sau một lượt user; nó "has the same authority as the top-level `system` field, but because it is appended to the end of the message history, it does not invalidate any cached prefix" — [Using the Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) (bậc 1)
- Magentic-One (AutoGen) làm rõ cách dựng context mỗi lượt: `_orchestrate_step` gọi `context = self._thread_to_context()` (toàn bộ thread), rồi **append** `UserMessage(progress_ledger_prompt)` vào cuối, gọi model lấy JSON; prompt ledger này **không** được lưu vào thread (chỉ có `instruction_or_question` được lưu). Prompt ledger mở đầu bằng "Recall we are working on the following request:\n\n{task}" — tức task gốc được nhắc lại ở cuối context **mỗi lượt** — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py), [_prompts.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_prompts.py) (bậc 1, source code, đọc 2026-10-19)
- Magentic-One outer loop: khi `n_stalls >= max_stalls`, orchestrator cập nhật fact sheet + plan rồi `_reenter_outer_loop`: **xóa** `_message_thread`, reset các agent, và thread mới bắt đầu bằng `ORCHESTRATOR_TASK_LEDGER_FULL_PROMPT` ("We are working to address the following user request: {task} … team … facts … plan") — [_magentic_one_orchestrator.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_magentic_one_orchestrator.py) (bậc 1)
- LangGraph supervisor: handoff là tool `transfer_to_<agent_name>` (mô tả mặc định "Ask agent '<agent_name>' for help"), trả `ToolMessage` "Successfully transferred to {agent_name}"; khi agent con trả về, `output_mode` mặc định `"last_message"` chỉ giữ message cuối (hoặc 2 message cuối nếu cuối là ToolMessage), `"full_history"` giữ toàn bộ; thêm cặp giả `AIMessage("Transferring back to {supervisor}")` + `ToolMessage("Successfully transferred back to …")` — [handoff.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/handoff.py), [supervisor.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/supervisor.py) (bậc 1)
- LangGraph supervisor có tool `forward_message` "Forwards the latest message from the specified agent to the user without any changes… preserve information fidelity" — chống mất thông tin khi supervisor viết lại kết quả — [handoff.py](https://github.com/langchain-ai/langgraph-supervisor-py/blob/main/langgraph_supervisor/handoff.py) (bậc 1)
- README langgraph-supervisor hiện ghi: "We now recommend using the supervisor pattern directly via tools rather than this library… gives you more control over context engineering" — [README](https://github.com/langchain-ai/langgraph-supervisor-py) (bậc 1, không rõ ngày ghi chú)
- OpenAI Agents SDK, handoff: "When a handoff occurs, it's as though the new agent takes over the conversation, and gets to see the entire previous conversation history", đổi được bằng `input_filter`; `nest_handoff_history` (beta, tắt mặc định) gộp lịch sử thành đoạn tóm tắt bọc trong `<CONVERSATION HISTORY>`. Agents-as-tools (`Agent.as_tool()`): input mặc định `{"input": "..."}`, và "the parent run's conversation state is not inherited automatically" — [handoffs.md](https://github.com/openai/openai-agents-python/blob/main/docs/handoffs.md), [tools.md](https://github.com/openai/openai-agents-python/blob/main/docs/tools.md) (bậc 1, docs trong repo)
- OpenAI Responses API có `previous_response_id`/Conversations để server giữ lịch sử, nhưng "Even when using previous_response_id, all previous input tokens for responses in the chain are billed as input tokens" — [Conversation state](https://developers.openai.com/api/docs/guides/conversation-state) (bậc 1, **chỉ qua snippet search**, không mở được trang)

### Ví dụ minh họa turn-by-turn (Messages API)
**Nhận định:** đây là ví dụ do researcher dựng, đúng định dạng docs ở trên; tên tool `run_subagent` lấy theo kiểu `run_blocking_subagent` trong prompt Anthropic; nội dung là giả định.

Lượt 1 — request (orchestrator):
```json
{
  "model": "claude-...",
  "system": "You are an expert research lead... (research_lead_agent.md)",
  "tools": [
    {"name": "run_subagent",
     "description": "Spawn a research subagent with a fresh context. It cannot see this conversation; put everything it needs in `prompt`. Returns the subagent's final report.",
     "input_schema": {"type": "object",
       "properties": {"prompt": {"type": "string"}},
       "required": ["prompt"]}},
    {"name": "complete_task", "description": "Submit the final report.", "input_schema": {"type":"object","properties":{"report":{"type":"string"}},"required":["report"]}}
  ],
  "messages": [
    {"role": "user", "content": "So sánh hệ thống thuế 3 nước Bắc Âu"}
  ]
}
```
Lượt 1 — response: `stop_reason: "tool_use"`, content = [text "Kế hoạch: 3 subagent…", `tool_use` id `toolu_A` (Thụy Điển), `tool_use` id `toolu_B` (Na Uy), `tool_use` id `toolu_C` (Đan Mạch)] — gọi song song.

Harness chạy 3 subagent; **mỗi subagent là một vòng lặp riêng** với request riêng: `system` = research_subagent.md, `messages` = [{user: `<task>` = chuỗi `prompt` của toolu_A}], không chứa lịch sử của orchestrator.

Lượt 2 — request (orchestrator), gửi lại toàn bộ:
```json
{
  "system": "…(y nguyên)…",
  "tools": ["…(y nguyên, để giữ cache)…"],
  "messages": [
    {"role": "user", "content": "So sánh hệ thống thuế 3 nước Bắc Âu"},
    {"role": "assistant", "content": [
      {"type": "text", "text": "Kế hoạch: …"},
      {"type": "tool_use", "id": "toolu_A", "name": "run_subagent", "input": {"prompt": "Research Sweden's tax system… output: dense fact list with sources…"}},
      {"type": "tool_use", "id": "toolu_B", "name": "run_subagent", "input": {"prompt": "…Norway…"}},
      {"type": "tool_use", "id": "toolu_C", "name": "run_subagent", "input": {"prompt": "…Denmark…"}}
    ]},
    {"role": "user", "content": [
      {"type": "tool_result", "tool_use_id": "toolu_A", "content": "<báo cáo cô đọng ~1-2k token của subagent A>"},
      {"type": "tool_result", "tool_use_id": "toolu_B", "content": "<báo cáo B>"},
      {"type": "tool_result", "tool_use_id": "toolu_C", "content": "Error: subagent hit tool-call limit", "is_error": true},
      {"type": "text", "text": "<system-reminder>Mục tiêu gốc: so sánh thuế 3 nước; còn thiếu: Đan Mạch</system-reminder>"}
    ]}
  ]
}
```
Lượt 3 trở đi: append tiếp cặp `assistant tool_use` → `user tool_result`; prefix (tools → system → messages cũ) không đổi nên đọc từ cache; kết thúc khi orchestrator gọi `complete_task` hoặc trả `stop_reason: "end_turn"`.

### Nhận định
- "Trạng thái" của orchestrator = chính mảng `messages` do harness giữ. Mục tiêu gốc được giữ vì (1) message user đầu tiên luôn nằm trong prefix gửi lại, (2) system prompt nhắc "query… serves as your primary goal", và (3) nhiều hệ chèn thêm bản nhắc task ở **cuối** context (Magentic-One progress ledger, Manus todo.md, system-reminder của Claude Code, mid-conversation system message).
- Hai cách kết quả subagent vào lại context: agent-as-tool (kết quả là `tool_result`, thường chỉ message cuối/tóm tắt) và handoff (subagent chiếm cả cuộc hội thoại, thấy toàn lịch sử trừ khi lọc). Đây là điểm khác cơ bản về "ai thấy gì".
- Magentic-One cho thấy hai mẫu chèn khác nhau: ledger "tạm" (append vào context chỉ cho một lần gọi, không lưu) và reset hẳn thread khi bế tắc (đánh đổi cache và lịch sử để lấy context sạch bám plan mới).

### Khoảng trống
- Không có tài liệu chính thức công bố nguyên văn system prompt hay nội dung `<system-reminder>` mà Claude Code chèn mỗi lượt (chỉ có các bản leak bậc 3, không dùng).
- Không mở được trang OpenAI conversation-state để trích đầy đủ; câu billing lấy từ snippet.

## Câu hỏi phụ 3b: Prompt giao việc cho subagent nên chứa gì? Có prompt thật được công bố không?

### Kết luận ngắn
Có, nhiều prompt thật đã mở nguồn. Các nguồn thống nhất một danh sách: **một mục tiêu cốt lõi, định dạng đầu ra, bối cảnh nền (vì subagent không thấy hội thoại cha), câu hỏi cần trả lời, nguồn/công cụ nên dùng và nên tránh, ranh giới phạm vi, ngân sách công sức (số tool call)**. Mức chắc chắn: **cao** (prompt gốc của Anthropic + docs Claude Code + source AutoGen).

### Phát hiện có nguồn
- Anthropic: mỗi subagent cần "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries"; chỉ dẫn ngắn kiểu "research the semiconductor shortage" khiến subagent làm trùng (một agent tìm khủng hoảng chip 2021, hai agent khác cùng tìm chuỗi cung ứng 2025) — [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Prompt lead mở nguồn, mục `<delegation_instructions>` liệt kê nguyên văn những gì phải có trong chỉ dẫn cho subagent: "Specific research objectives, ideally just 1 core objective per subagent."; "Expected output format…"; "Relevant background context about the user's question and how the subagent should contribute to the research plan."; "Key questions to answer…"; "Suggested starting points and sources to use; define what constitutes reliable information… and list any unreliable sources to avoid."; "Specific tools that the subagent should use…"; "If needed, precise scope boundaries to prevent research drift." — [research_lead_agent.md](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md) (bậc 1, không rõ ngày commit; đi kèm bài 2025-06)
- Cùng prompt: chỉ dẫn được đặt trong tham số `prompt` của tool `run_blocking_subagent`; "maintain extremely high information density while being concise"; ví dụ mẫu một task description tốt (semiconductor supply chain) kết thúc bằng yêu cầu đầu ra "compile your findings into a dense report of the facts… with specific timelines and quantitative data"; "Avoid overlap between subagents"; "NEVER create a subagent to generate the final report"; số subagent "default to using 3", "Never create more than 20" — [research_lead_agent.md](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md) (bậc 1)
- Prompt lead kết thúc bằng câu neo mục tiêu: "You have a query provided to you by the user, which serves as your primary goal… No clarifications will be given" — [research_lead_agent.md](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md) (bậc 1)
- Prompt subagent: "You have been given a clear <task> provided by a lead agent"; tự đặt "research budget" (dưới 5 tool call cho việc đơn giản, ~5 trung bình, ~10 khó, tối đa ~15); giới hạn cứng "under a limit of 20 tool calls and under about 100 sources"; vòng OODA; báo xung đột về cho lead thay vì tự chọn; kết thúc bằng tool `complete_task` với "detailed, condensed, complete, accurate report to the lead researcher" — [research_subagent.md](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_subagent.md) (bậc 1)
- Quy tắc scale công sức trong bài blog: "Simple fact-finding requires just 1 agent with 3-10 tool calls", so sánh trực tiếp "2-4 subagents with 10-15 calls each", nghiên cứu phức tạp "more than 10 subagents" — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Claude Code: subagent "starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read. Claude composes a delegation message that summarizes the task"; subagent nhận "only this system prompt plus basic environment details like the working directory, not the Claude Code system prompt" (nhưng có nạp CLAUDE.md, trừ Explore/Plan) — [Create custom subagents](https://code.claude.com/docs/en/sub-agents) (bậc 1, truy cập 2026-10-19)
- Agent SDK: "The only content you pass from parent to subagent is the Agent tool's prompt string, so include any file paths, error messages, or decisions the subagent needs directly in that prompt." Subagent nhận: system prompt riêng (`AgentDefinition.prompt`) + prompt của Agent tool + CLAUDE.md + tool definitions; không nhận: lịch sử/tool result của cha, system prompt của cha — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1)
- Claude Code: field `description` của subagent quyết định khi nào được giao việc ("Claude uses each subagent's description to decide when to delegate"; thêm "use proactively" để khuyến khích); các description chiếm context, cảnh báo khi tổng vượt 15.000 token — [Create custom subagents](https://code.claude.com/docs/en/sub-agents) (bậc 1)
- Ngân sách/giới hạn ở mức harness: `maxTurns` (hết lượt → output đánh dấu partial), độ sâu lồng mặc định 3 tầng, tối đa 20 subagent đồng thời, `max_budget_usd` — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents) (bậc 1)
- OpenAI Agents SDK `RECOMMENDED_PROMPT_PREFIX` (nguyên văn): "# System context\nYou are part of a multi-agent system called the Agents SDK, designed to make agent coordination and execution easy. Handoffs are achieved by calling a handoff function, generally named `transfer_to_<agent_name>`. - Magentic-One giao việc qua field JSON `instruction_or_question`: "What instruction or question would you give this team member? (Phrase as if speaking directly to them, and include any specific information they may need)"; kèm `next_speaker`, `is_request_satisfied`, `is_in_loop`, `is_progress_being_made`, mỗi field có `reason` + `answer` — [_prompts.py](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_magentic_one/_prompts.py) (bậc 1)

For math problems, use math_agent." — [langgraph-supervisor README](https://github.com/langchain-ai/langgraph-supervisor-py) (bậc 1)

### Nhận định
- Checklist prompt giao việc rút từ các nguồn trên: (1) một mục tiêu duy nhất; (2) bối cảnh: task gốc của user và vai trò của phần việc này trong kế hoạch, cộng mọi dữ kiện (đường dẫn, lỗi, quyết định) mà subagent không tự thấy được; (3) câu hỏi cụ thể cần trả lời; (4) nguồn/tool nên dùng, nguồn nên tránh, tiêu chí tin cậy; (5) ranh giới (cái gì *không* thuộc phần mình, để khỏi trùng với subagent khác); (6) ngân sách (số tool call / lượt / thời gian); (7) định dạng đầu ra và độ dài (vd báo cáo dày đặc dữ kiện, ~1–2k token, kèm nguồn, ghi xung đột). Mục (2) là mục hay bị thiếu nhất vì subagent bắt đầu từ context trắng.
- Prompt của Anthropic tách vai: lead chỉ lập kế hoạch/tổng hợp, subagent làm nghiên cứu; Magentic-One dồn mọi điều phối vào một JSON có cấu trúc mỗi lượt. Cả hai đều buộc orchestrator **tự đánh giá tiến độ so với task gốc** trước khi giao bước tiếp.
- Chính brief giao cho researcher này (sub-questions, nguồn gợi ý, ràng buộc, ngoài phạm vi, đường dẫn lưu notes, giới hạn ~25 tool call) là một ví dụ sống của checklist trên.

## Câu hỏi phụ 3c: Hướng dẫn context engineering về những gì đưa vào mỗi lượt; hệ quả của prompt caching với context append-only

### Kết luận ngắn
Đồng thuận: context là tài nguyên hữu hạn, cần "smallest possible set of high-signal tokens"; subagent dùng để cô lập phần khám phá và trả về bản tóm tắt cô đọng; giữ prefix (tools → system → lịch sử) **ổn định và chỉ append** để trúng cache; nhắc mục tiêu ở cuối context (recitation) thay vì sửa prefix. Mức chắc chắn: **cao** cho Anthropic (bậc 1, đọc trực tiếp), **trung bình** cho chi tiết Manus (chỉ qua snippet trích trang gốc).

### Phát hiện có nguồn
- Định nghĩa: context engineering là "the set of strategies for curating and maintaining the optimal set of tokens (information) during LLM inference"; context "must be treated as a finite resource with diminishing marginal returns", LLM có "attention budget"; mục tiêu là "finding the smallest possible set of high-signal tokens" — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (bậc 1, 2025-09-29)
- System prompt ở "right altitude": tránh hai cực, "hardcoding complex, brittle logic" và chỉ dẫn mơ hồ cấp cao "wrongly assumes shared context"; tool set phình to/chồng chéo là "one of the most common failure modes" — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (bậc 1, 2025-09-29)
- Just-in-time: agent giữ "lightweight identifiers (file paths, stored queries, web links, etc.)" rồi nạp khi cần, thay vì nhét hết vào context — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (bậc 1)
- Ba kỹ thuật cho tác vụ dài: compaction (Claude Code tóm tắt lịch sử, giữ quyết định kiến trúc, bug chưa giải quyết, chi tiết cài đặt, bỏ tool output thừa, rồi tiếp tục với bản tóm tắt + "the five most recently accessed files"); "tool result clearing" là dạng compaction "safest lightest touch"; structured note-taking (NOTES.md, to-do list của Claude Code, ví dụ Claude chơi Pokémon đọc lại ghi chú sau khi reset context); sub-agent architectures — sub-agent "return only a condensed, distilled summary of its work (often 1,000-2,000 tokens)" dù đã dùng hàng chục nghìn token khám phá, lead giữ kế hoạch cấp cao — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) (bậc 1, 2025-09-29; một phần là diễn giải do công cụ giới hạn trích dẫn 125 ký tự)
- Hệ Research của Anthropic: LeadResearcher lưu plan vào Memory vì context vượt 200.000 token sẽ bị cắt; subagent nên lưu kết quả ra hệ thống ngoài và "pass lightweight references back to the coordinator" để tránh "game of telephone"; lead chạy subagent đồng bộ (gây nghẽn); agent dùng ~4× token so với chat, multi-agent ~15×; token usage giải thích 80% phương sai trên BrowseComp; multi-agent (Opus 4 lead + Sonnet 4 subagent) hơn single-agent Opus 4 90,2% trên eval nội bộ — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (bậc 1, 2025-06-13)
- Prompt caching: thứ tự prefix là "`tools`, `system`, and `messages` (in that order)"; "Modifying tool definitions (names, descriptions, parameters) invalidates the entire cache"; đổi `tool_choice` hoặc thêm/bớt ảnh chỉ ảnh hưởng block messages; TTL mặc định 5 phút (có 1 giờ); ghi cache 1,25× (5 phút) hoặc 2× (1 giờ) giá input, đọc cache 0,1× (ngoại lệ 0,05× trên Opus 5.5/Sonnet 5.5, 0,025× trên Fable 5.1/Mythos 5.1); lookback tối đa 20 vị trí mỗi breakpoint; với cuộc hội thoại tăng dần, "earlier content never changes, so the next request's lookback finds the prior write"; automatic caching tự dời breakpoint tới block cuối — [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) (bậc 1, truy cập 2026-10-19)
- Context editing (`clear_tool_uses_20250919`): API xóa tool result cũ nhất khi vượt `trigger`, giữ `keep` cặp gần nhất, thay bằng placeholder; "applied server-side before the prompt reaches Claude. Your client application maintains the full, unmodified conversation history"; đánh đổi: "Invalidates cached prompt prefixes when content is cleared" → dùng `clear_at_least`; kết hợp memory tool: Claude nhận cảnh báo để lưu thông tin trước khi bị xóa — [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) (bậc 1)
- Compaction phía server: "replaces the older turns of a conversation with a summary that Claude writes on the server… because response quality degrades as a conversation grows"; hai chế độ on-demand (beta `compact-2026-09-04`) và theo ngưỡng token; có thể giữ nguyên văn các lượt gần nhất — [Compaction overview](https://platform.claude.com/docs/en/build-with-claude/compaction) (bậc 1, truy cập 2026-10-19)
- Mid-conversation system message append vào cuối nên "does not invalidate any cached prefix that came before it" — cách chèn chỉ dẫn/nhắc mục tiêu thân thiện với cache — [Using the Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages) (bậc 1)
- Manus (Yichao "Peak" Ji): "KV-cache hit rate is the single most important metric for a production-stage AI agent"; tỉ lệ input:output trung bình ~100:1; với Claude Sonnet "cached input tokens cost 0.30 USD/MTok, while uncached ones cost 3 USD/MTok—a 10x difference"; timestamp chính xác tới giây đầu system prompt là lỗi phổ biến làm hỏng cache; "Avoid modifying previous actions or observations. Ensure your serialization is deterministic" (thứ tự key JSON không ổn định "can silently break the cache"); không thêm/bớt tool giữa chừng — [Context Engineering for AI Agents: Lessons from Building Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) (bậc 1, 2025-07; **chỉ qua snippet search**, trang bị proxy chặn)
- Manus recitation: "A typical task in Manus requires around 50 tool calls on average. By constantly rewriting the todo list, Manus is reciting its objectives into the end of the context. This pushes the global plan into the model's recent attention span, avoiding 'lost-in-the-middle' issues and reducing goal misalignment." — [Manus blog](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) (bậc 1, 2025-07; qua snippet search)
- Manus "mask, don't remove": thay vì gỡ tool, che token tool không hợp lệ lúc decode (logit masking / prefill tiền tố tên tool) — chi tiết cơ chế chỉ thấy ở bản tóm tắt thứ cấp [tianpan.co](https://tianpan.co/blog/2026-03-02-context-engineering-lessons-from-manus) (bậc 2–3, 2026-03); phần nguyên tắc "avoid dynamically adding or removing tools mid-iteration" có trong snippet trang gốc Manus
- Thông tin thứ cấp chưa kiểm được: Manus ban đầu để executor tự quản todo.md, tốn khoảng 1/3 số action, sau chuyển sang planner sub-agent — chỉ thấy trong tóm tắt search từ blog thứ cấp (bậc 3), không trích làm bằng chứng

### Nhận định
- Vì mỗi lượt gửi lại toàn bộ, thiết kế orchestrator chịu hai lực ngược nhau: (a) muốn sửa/tóm tắt/xóa lịch sử để chống context rot, (b) muốn append-only để trúng cache (đọc cache rẻ 10–40 lần). Lời giải chung của các nguồn: giữ phần đầu (tools, system, task gốc) bất biến; đưa trạng thái động (todo, ledger, reminder) vào **cuối**; khi buộc phải cắt thì cắt một lần đủ lớn (compaction, `clear_at_least`, hoặc reset thread như Magentic-One) rồi xây lại prefix mới.
- Subagent là cơ chế context engineering cho orchestrator: tool_result của subagent chỉ đưa vào ~1–2k token đã chưng cất, nên lịch sử của orchestrator tăng chậm và task gốc không bị chìm giữa hàng chục nghìn token khám phá. Cái giá: mất chi tiết (game of telephone), được giảm bằng việc ghi artifact ra file và trả tham chiếu.
- Thay tool set giữa chừng (vd thêm/bớt tool spawn subagent theo giai đoạn) làm mất toàn bộ cache theo docs Anthropic, củng cố khuyến nghị "mask, don't remove" của Manus.
